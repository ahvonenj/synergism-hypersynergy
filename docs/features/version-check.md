# Version check (`HSGithub`, `hs-core/github/`)

The rainbow border on the mod icon and "New version available!" in the panel title. Checked at load, then every 30 minutes until a newer version is found, and by CHECK VERSION (Tools tab). Static, not an `HSModule`.
- **The tags read are those of the repo the mod was loaded from** (`window.__HS_REPO`, GitHub's tags API, one page of 100). The browser loaders set it. On Steam the injector sets it, with `__HS_VERSION`, from the mod URL of the launch (loader 0.2.9 and later; a jsDelivr URL only, so nothing on the Local channel). The game runs with `contextIsolation: true`, so the injector puts them in a script of their own, added before the mod's: a statement in front of the mod's code would cancel its `"use strict"`. With no repo known (bookmarklet, a game patched by a loader up to 0.2.8), the Live repo is read (`HSGlobal.Release.githubOwner`).
- **Live players follow stable tags only** (`v2.14.4`, `v2.14.4b`). **A player of another repo (the Dev channel) follows its dev builds too** (`v2.14.4b-dev4`). A stable tag is pushed to the Dev repo only when Dev serves that Live build (`docs/dev/releasing.md`, "Merging a Live release into Dev").
- **A dev build comes after the release it is named from**: `v2.14.4b < v2.14.4b-dev1 < v2.14.4c`, and `v2.14.4-dev3 < v2.14.4a` (`compareVersionTags`, `hs-version-tags.ts`). `compareVersions` in `scripts/release-version-tags.mjs` (the release helper's) sorts the same way; `scripts/tests/test-version-tags.cjs` checks it. Three old tags on Live (`v2.14.1-dev` to `v2.14.3-dev`) were made the other way round.
- **A Dev player is told once about each Live release above their build**: a notification ("Live channel: vX was released"), the tag kept under the `HSStorage` key `version-check`. No rainbow mark, because a reload gives them the same Dev build. "Above" is by tag name, not by content. The latest Live release is also logged at each check and added to CHECK VERSION's answer. It costs Dev players a second request per check (GitHub allows 60 per hour without an account).
- GitHub returns the tags sorted by version, highest first (seen on both repos, not documented). Past 100 tags the oldest ones leave the page, which changes nothing here.
- **Known limit:** on the Dev repo any hyphenated tag counts as a build and build names compare alphabetically, so a tag like `v2.14.4b-test` would rank above every `-devN` and give Dev players a lasting rainbow mark. Restricting `devTagPattern` (`hs-version-tags.ts`) to `-dev<number>` would fix it; not done while no such tag exists.
- **To test without a release:** lower the `package.json` version below the latest Dev tag and restart the dev server (rainbow mark); below the latest Live tag too, for the Live notification. Put the version back afterwards.
