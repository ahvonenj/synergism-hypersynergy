# Timed save export (`HSAutoExport`, `hs-modules/hs-auto-export.ts`)

The code is in three files: `hs-auto-export.ts` (the clock and the click), `hs-auto-export-folder.ts` (`HSAutoExportFolder`: folder choice, permissions, file retention and their buttons), `hs-auto-export-store.ts` (`HSAutoExportStore`: the IndexedDB `hs-auto-export`). Types in `types/module-types/hs-auto-export-types.ts`; a node test in `scripts/tests/test-auto-export.cjs` (`npm run test:auto-export`).

The "Export the save every X minutes" setting (`autoExportSave`, a number with its switch, Save page, off by default), "Export loadout" (`autoExportSaveLoadout`), the export folder buttons and "Keep only the last X files". No patcher feature is needed.
- **It clicks the game's own `#exportgame`** (the vanilla save, with the export rewards). The rewards and the save are computed inside the click (`exportSynergism` up to `saveSynergy()` is synchronous); only the output comes a few microtasks later.
- **The clock is the game's `player.lastExportedSave`**, checked every 10 s: an export by hand restarts it, a reload doesn't. Without the live player (bookmark load), it counts from the page load and from clicks on `#exportgame`.
- **A file even in clipboard mode:** `#saveType` is unticked for the click and ticked back in the next task (`exportData` reads `.checked` after the awaits). Setting the property fires no event, so the stored `copyToClipboard` preference is untouched.
- **Export loadout** (`HSAmbrosia.runWithLoadout`): the loadout is loaded, the export clicked, then the player's tree is put back, all in one synchronous step. The tree comes back through the slot the game marks, else the one shown as loaded (silver border) when it holds exactly the live tree; unsaved changes are kept (`#loadTreeThroughSlot`, needs `exposedPlayer` and `__HS_validateBlueberryTree`), else the marked slot is reloaded. With no slot to come back to, the loadout is loaded anyway and stays loaded (chosen over "no slot = no switch"). A locked or empty loadout is not loaded. The player's SAVE/LOAD mode is put back.
- **The exported file holds the export loadout as its live tree** (the save is made inside the click), and each export costs two loadout loads, each restarting the ambrosia bars.
- **The Heater's "Sync All Loadout Settings" sets the export loadout to the Quarks slot**, or None without one, like the other loadout settings, even for a player who chose None: not an exception, the button's tooltip lists it.
- **Skipped while autosing is active** (autosing exports for its quarks with its own loadout) and while the offline popup is open.
- **A plain download opens a "Save as" dialog on Steam** (the game's Electron main has no `will-download` handler, and the preload is sandboxed, so the mod can't write a file that way). Hence the export folder below, chosen over a loader patch of the game's main process. On Steam without a folder nothing is exported, and a notification says to choose one (once per session, when an export is due).
- **Export folder** ("Choose folder" / "Forget folder" buttons, File System Access API: Steam, Chrome, Edge; not Firefox, which keeps plain downloads). The folder handle and the names of the files written are kept in IndexedDB (`hs-auto-export`), not in `HSStorage`: a handle can't be stored as text, and the list must not travel in a backup file.
- **With a folder, the game's download is intercepted**, for the timed export only: the game exports through a click on a link it builds (`a#downloadSave`, the name in `download`, the save after the comma of its `data:` URL). A capture listener on `document` cancels that click and writes the file. The click comes in the microtasks of the Export click, so the flag that arms the listener is cleared in the next task. The name is cleaned first (a download lets the browser do it): `<>:"/\|?*` and control characters become `_`.
- **The folder is lost at every page load** (`queryPermission` answers `prompt`, a write throws `NotAllowedError`) and given back by `requestPermission` at a click or a key press: with no dialog on Steam, with Chrome's own prompt in Chrome. It is asked in the task after the input, so the click that turns the setting on counts, and only while the setting is on. An export due before that asks for a click with a notification.
- **Steam refuses Downloads, Documents and the Desktop themselves without a word**: the picker closes, its promise never settles, and every later picker of that window throws "File picker already active" until a reload. So on Steam a pick with no answer 1.5 s after the window got the focus back is given up, with a notification, and the next pick goes through a new hidden iframe, which has a picker of its own (tested on Steam). Frames are never removed: a folder picked through one belongs to it. Chrome shows a dialog and opens its picker again, so none of this runs there.
- **"Keep only the last X files"** (`autoExportSaveKeep`, on, 20): only names from the module's own list are ever removed, so anything else in the folder is safe. With the setting off the list is capped at 1000 names, files stay.
- **A failed write** (folder removed or renamed): a notification; in a browser the file is downloaded instead, on Steam it is not (the rewards were collected, the save is in the game).
- **Settings buttons get their help text as `title`** (`#buildSettingBlock`, all of them: they had none). A help text is put in an HTML attribute unescaped (`HSUIC.#getPropString`): no double quote in one. The two folder buttons share a line through the `hs-inline-button` class, given by group name in `#buildSettingBlock` (`save-export`, as the Auto-Sing strategy buttons), and are sized by id in `hs-panel-core.css`. The first one's text is rewritten by the module at each tick (the panel is built after the modules).
- Chrome asks once to allow "multiple downloads" when a download follows another with no click or key press in the page between them; if refused, nothing downloads and the mod can't tell.
- Not built (not asked): an export folder for the player's own exports by hand (they still open "Save as" on Steam).
- Tested headless by driving the real module against a fake game, an OPFS folder standing for the picked one (`scripts/harness/`).
