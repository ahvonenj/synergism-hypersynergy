# Autosing strategy editor: strategy and actions windows

The autosing docs: `autosing.md` (the run), `autosing-strategies.md` (strategy format, conversions, default strategies), `autosing-editor.md` (strategy and actions windows). Players' guide: `docs/data/guides/autosing.md` (published to the website and wiki by `scripts/tools/build-docs.py`), updated with any change players see.

The strategy window (`ui/hs-autosing-strategy-modal.ts`) edits a strategy's name and phases; each phase's steps are edited in an actions window (`ui/hs-autosing-challenge-modal.ts`). There is no phase window (chosen over restyling the old one). Both windows' questions use the `hs-editor-overlay*` classes.

Tested headless: the real windows on a fake page, with stubbed HSUI and storage and a fake `Modal` that honours `position` (`scripts/harness/README.md`, "Mod classes on a fake game page").

## Strategy window
- **Phase rows**: "Phase N:" (left) … "start →" (right, next to the dropdown; the AOAG row unchanged) [end ▾] [✎ k steps] [×]. ✎ opens the phase's actions window; "0 steps" in red (saving refuses an empty phase).
- **Phases chain**: the first phase always starts at "start", each other at the previous end (`#fixPhaseChain`). An end dropdown offers only ends before the next phase's end (the last one: up to "end"), so a change never breaks later phases; a plain list in game order (a "Common"/"Other" grouping was tried and dropped: messier).
- **Adding**: an "Add phase until… ▾" dropdown (picking an end adds the phase; chosen over an Add button with a default end), hidden once the last phase ends at "end".
- **Inserting**: a small round "+" dropdown on each phase row's left border, in the gap above it. It lists the points strictly between that phase's start and end, under a heading "Insert a phase from <start> to:" (an `<optgroup>` label). Picking one adds an empty phase "start → point" before it, the phase keeping its steps and starting at the point. No "+" when there is no room.
- Rejected: free starts with a "missing link" warning (saving must refuse a gap anyway: autosing stops on an uncovered stage); an AOAG + "singularity → end" template (not worth it: saving already requires phases up to "end").
- **Works on a copy**; phase objects are kept (end changed in place) so the actions window's Save writes into its phase's `strat`.
- **Cancel and ×** show "Discard unsaved changes?" when the copy (name included, keys order ignored, `canonicalJson`) or one of its open actions windows has changes, and close them all.
- **× on a phase whose actions window is open**: overlay "Phase N's actions window is open. Delete the phase and close it?" [Keep] [Delete] (only that window closes).
- **Update Strategy** is refused (error line "Save or close the actions windows first") while an actions window has unsaved changes; otherwise they close with it. The error line is cleared at each change.
- **Deleting a strategy in the panel** is refused while a strategy window edits it (`HSAutosingStrategyModal.showEditorOf`, brought to the front): its Update would save it again.

## Several windows of a kind
- **Strategy windows**: a static list in `HSAutosingStrategyModal`, one per key: "create" (one new strategy window at a time: nothing tells two blank ones apart, and a double click would open two), `edit:<name>`, `copy:<default name>` (viewing a default strategy and editing a player's copy of it are two: both are wanted, for comparing).
- **Actions windows**: a `Map` per strategy window, keyed by the phase object (follows "+" inserts and deletes), so phase 1 of two strategies can be open at once. Their titles follow their phase's start/end (`setTitle`, at each redraw); their button is "Save" (it only saves into the strategy window's copy).
- **Opening one already open** brings it to the front with a warning (`"X" is already open in a strategy window`, `A new strategy window is already open`, `Phase N's actions window is already open`); still opening (a double click): nothing. Listed before the first `await`. `openAutosingChallengesModal` returns the window at once; its `close()` works during the fade-in.
- **Placement**: a new window opens 30 px right of and 10 px below the last open one of its kind (strategy windows: all of them; actions windows: those of the same strategy window); the first one at HSUI's place.
- **Each window works on its own copy and finds its elements inside itself** (never page-wide ids). Ctrl+Z / Ctrl+Y go to the actions window last clicked.
- Two windows on different strategies don't know about each other: saving to a name that exists is refused by `saveStrategyToStorage`. Not looked at: importing a strategy in the panel while its window is open.

## Actions window: step list
- **Numbers**: each step from 1 (IF rows too, "Jump here" rows not), the special action's id after its label; the logs use the same numbers (`autosing.md`).
- **Rows**: the edited row (✎) is marked orange; "Jump here" rows say their IF's step number and IF rows where they jump ("→ step N" / "→ end of phase"), both in grey; the hovered IF pair is outlined violet (orange = edited step); comments grey italics. An IF whose target is at or before its own step is a loop: "↺" on both rows.
- **Links**: an IF's "→ step N" and a "Jump here" row's "(IF step N)" are links. A click flashes the other row violet, after scrolling the list just enough to show it plus the row past it, whatever that row is (the list's own `scrollTop`, never `scrollIntoView`; smooth). A row already fully in view: no scroll, even when its neighbour is cut off. Centring it was tried and rejected.
- **IF targets are step indices.** Adding/deleting a step shifts them (`#shiftJumpTargets`; a target at a deleted index stays). Dragging a step does NOT: a target keeps its place in the list (making targets follow their step was tried and felt wrong in use, "I move it myself where I want"; don't propose it again).
- **Dragging**: one routine (step, "Jump here" row, Add Here separator); drop place = number of steps whose middle is above the mouse; the list is redrawn on each change. In add mode a drag/delete keeps the typed fields. The list auto-scrolls when the mouse is within 40 px of its top/bottom edge or past it (faster nearer the edge, up to 12 px per frame, a `requestAnimationFrame` loop on the last mouse position).
- **⧉ duplicates a step** right after it, added as a new step there (targets shifted as for an add; a copied IF gets a new id and the original's target).

## Actions window: fields and edit mode
- **One table, `FIELD_ROWS`** (label, initial value, `shown` rule on the selected action and IF mode, `load` from a step, `check`): a new field is a row there plus a line in `#buildStep`.
- **Fields an action doesn't use are hidden**, never greyed or disabled. Stored C15 mode has its own Multiplier field and a text line instead of Value. "Max jumps (0 = no limit)" is shown in both IF modes; a capped IF's grey meta line ends with "Max jumps: N" (`autosing-strategies.md`, "IF steps").
- **Special Action dropdown**: each option starts with its id (easier to read there); the ids stay plain text (colouring only them needs a customizable select or a mod-built dropdown: left as is). `<optgroup>`s by id ranges (`ACTION_GROUPS`; an action in none of them lands in "Other"): Exit and Ascend, Game actions (+ Forge), Condition, Challenges (211–215 + C1–C10), Ambrosia loadouts, Corruption level, AOAG and Autosing.
- **Families** (`ACTION_FAMILIES`): 601–610 are one entry "601-610 - C1-C10 until no more completions" + Challenge # (1–10); 701–709 one entry "701-709 - Forge Auto-Buy Toggle" + a "Forge item" dropdown (names = label after "Forge Auto-Buy Toggle - "). Editor only: a step still holds 601–610/701–709, so autosing, logs and the step list (long labels) are unchanged, no runtime cost. 211–214 kept as separate entries. A note under the dropdown explains C1–C10, naming the form's fields (a `shortLabel` for 601–610 was tried first, dropped with the families).
- **Number fields are checked as they are typed** (`#checkFields` on every input/change and field show; `check` is a function of the context: Challenge # is 1–10 for the C1–C10 family). Empty/non-number refused; Challenge # and If Challenge whole 1–15; Min Completions ≥ 0 (not 1: 0 = enter the challenge then wait inside, 123 steps in the default strategies); Corruption Level and Max jumps whole ≥ 0; waits and Max Time ≥ 0; Multiplier and IF Value any number. Never corrected.
- **A bad field turns red** and the Add/Update button shows the first one's reason in its own box (red, one line) and refuses while any is bad (the agreed "red line under the button" was dropped for the no-resize rule).
- **Enter in a typed field** (number inputs, comment; not a dropdown; not while composing) = Add/Update (once refused as too hidden: the "?" box lists it). Escape refused.
- **Edit mode**: ✎ loads every value of a step, so Update keeps the hidden ones. The button says "Update step N" with a small Cancel on its right (same as ✎ again, which is hidden). Edit mode follows the edited step through a drag, a duplicate or a delete, renumbered, the typed fields kept (`#keepEditing`, by object identity); deleting the edited step itself ends it; Undo/Redo leave it (they swap the whole list). Leaving edit mode (Update, Cancel, ✎ again, deleting the edited step) clears the comment field, which held the edited step's comment.

## Actions window: footer, undo, closing
- **Footer**: "?" (a help tooltip: shortcuts, drag, IF targets, links, ↺, fixed time; `HELP_LINES`), Undo, Redo, then "Fixed time".
- **Fixed time** (seconds, 3 decimals = ms precision): every Wait before (measured from the end of the previous step at runtime, so they add up; IF steps included) plus Wait inside of standard challenges (only waited when the minimum is reached before Max Time) and 601–610 (always); nothing else in a step sleeps a fixed time. The list is run once, IF jumps not followed.
- **Undo**: a snapshot (steps + separator) before each add, changed Update, duplicate, delete, and one per drag that changed the steps; a separator move alone is not a change. Undo/Redo leave edit mode and keep typed fields in add mode. Redo: undone lists on a second stack, emptied by any new change.
- **Shortcuts**: Ctrl+Z undoes, Ctrl+Y / Ctrl+Shift+Z redo, when the page's last mouse press was in this window and focus is not in a field (fields keep their own undo), not under the overlay. The document listeners remove themselves at the first event after the window is gone.
- **"Changed"** = the copy differs from the saved steps, keys order ignored (`canonicalJson`): undoing everything is unchanged; a ✎ Update of an old step without `challengeWaitBefore` adds it (0) and counts as a change.
- **The window works on a deep copy** (Cancel undoes IF target shifts). Cancel and the window's × (a listener on the × itself that stops the click before HSUI's handler on the window) show an in-window overlay "Discard unsaved changes?" [Keep editing] [Discard] when changed (overlay chosen over an armed button).
