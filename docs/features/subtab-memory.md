# Remembered subtabs (`HSSubtabMemory`, `hs-modules/hs-subtab-memory.ts`)

The "Remember last used subtab" setting (`rememberSubtabs`, UI page, on by default). No patcher feature is used, so it works for bookmarklet players too.
- **A tab's subtab is noted when the tab is left**, from the `active-subtab` class its buttons still carry (see "A reset sends the player to Buildings"). It runs from `HSGameState`'s `MAIN_VIEW` change, inside the `MutationObserver` callback, so before the next paint.
- **It is clicked back when the player opens the tab** and the game shows the tab's first visible subtab (its index was reset). A subtab that is not the first was picked on purpose (a game shortcut, the mod) and is left alone.
- **"By the player" means a trusted click, key or touch event is being handled** (`window.event`: a click, a hotkey, a dialog's OK). Not any trusted event: `HSUtils.yield()` and the sleep worker resume the mod's code inside a trusted `message` event, which made autosing's DOM stage read restore Settings over Stats and stop. The mod's own tab clicks come from timers, promises and those messages: the stage read, the settings fixer, `#ensurePatcherExposure`. Those tabs are not restored, and not noted when left, unless the player picked a subtab there meanwhile.
- **`openForPlayer(view)` opens a tab for the player, on its remembered subtab.** Autosing uses it to bring their tab back. It also notes the tab first when its change of tab hasn't been reported yet (left and reopened within one task), so the subtab picked just before is the one restored. The caller checks that the tab's button is visible.
- **The first time the player opens a tab after a page load**, the note is applied whatever the tab shows, and with no note the first subtab is shown. That is what undoes a loader's visit to Settings > Stats. Not on a bookmark load, where what the tabs show is the player's.
- **A locked subtab keeps its note**, tried again each time the player opens the tab.
- **Subtabs come from `HSGlobal.HSGameState.viewProperties`**, not from the page: the Runes row also holds the auto-sacrifice button. That list is built from each tab's `*_VIEW_BUTTON_IDS` record (`hs-gamestate-types.ts`), the one place that names subtab buttons; a subtab missing from it is never remembered. Settings > Messages (only shown with unread messages) is listed: while hidden it counts as locked, like any other.
- **Stored under its own `HSStorage` key** (`subtab-memory`), written when a note changes and when the page goes away (`pagehide`, for the tab on screen). A stored entry is only kept when it names a listed subtab of its own tab, so a shared backup file can't make the mod click anything else.
- **Turning the setting off forgets everything** at the next tab change, so turning it back on doesn't bring back old subtabs.
- Limits: when a reset happens while the player is on Buildings, Buildings' own subtab is lost. A game button that opens another tab on its first subtab would be overridden.
