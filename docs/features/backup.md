# Backup (`HSBackup`, `hs-core/hs-backup.ts`)

The "Backup & Restore" section of the Tools tab: the game save, the mod's stored data, the game's preferences and the logs in one `[HS] Synergism save backup <date> S<singularity> E<exalt> (highest S<highest>).json` file (`E<exalt>` only inside an Exalt, numbered as on the game's Exalt tab). Not an `HSModule`, static only.
- **Mod data is every `localStorage` key under the `hs-` prefix**, copied as stored (settings, strategies, hidden dialogs, icons, ambrosia state), so a new store is included without touching this code. The dev tools' key is left out; its name is put together at runtime, because the full string must stay out of the release bundle.
- **The save is the game's own stored string** (`localStorage.Synergysave2`, the same content as the game's export file), read after a manual save (`captureSave`, shared with the dev tools' snapshots: the game saved when the btoa hook captured the save or the stored one changed). No export reward. During a time warp the game refuses to save, and so does the export.
- **The file always has an `info` block** (mod version, date, Steam or browser, which patcher features are present, game language, number locale, user agent). Logs are one string per line (`HSLogger.getLogLines()`: the Log tab's lines plus the ones waiting for that tab). Neither is ever imported.
- **The manual backup also has `diagnostics.heater`**: the `hs_data` of `dumpDataForHeater()` (PseudoCoin levels, quark bonus, events, the mod's own results), the data a save doesn't hold. Built first, so the file's save is taken after the dump's save click; it waits on the network (the dump refreshes the fetched data), so `#export` is async and a second click meanwhile does nothing. A failure writes `diagnostics.heaterError` instead and the backup is still made. Never imported; the import modal only mentions it. The automatic backup before an import has none.
- **An import writes `localStorage`, then reloads the page.** The game and the mod load what was written as at any page load, so autosing, GDS, the dialog queue and the "Load from file" handler are not involved. `importSaveAndReload(save)` does the same for a save alone, with no modal and no backup first (the dev tools' Restore). A page load and the game's own import both end in `reloadShit()`.
- **Until the page is gone, writes to the imported keys are blocked** (`Storage.prototype.setItem`/`removeItem`/`clear` replaced). The reload is not immediate, and meanwhile the game's autosave would put the old save back, and the mod's 250 ms settings save the old settings.
- **The save is checked the way the game does at load** (base64 JSON, `exporttest` `'YES!'` or `true`). Anything else is refused, the old LZ-compressed saves among them: at load the game runs `localStorage.clear()` for those, which would wipe the mod's data.
- **A file is untrusted** (players share them): only `hs-` keys with string values are written, never the dev tools' key, and what the modal shows from the file is set as text.
- **Importing mod data is an exact restore:** the mod's keys missing from the file are removed. If a write fails, everything is put back and nothing reloads.
- **The backup before an import takes two clicks.** The first downloads the current state, the second imports. On Steam a download opens a "Save as" dialog (the game's Electron main has no download handler), and a reload before the file is written would lose it.
- **"Skip offline progress" (under Save in the import modal, unticked by default, not remembered)** sets the save's `offlinetick` to now before it is written, so the game counts no offline progress at load. Only that field: the code timers still count the time away and a new day still gets its daily reset, so the player never loses what the game would give them. Greyed out while Save is unticked or missing.
- **The save's clock fields** (`shiftSaveClock`, shared with the dev tools' Restore, which moves all of them): `offlinetick` (offline progress); `rngCode` (Add code uses) and `promoCodeTiming.time` (the Time code's size), moved forward by the time since the save; `dayCheck`, the date of the last daily reset, set to today's local midnight (as the game writes it) so a save from an earlier day gets no daily reset (counters zeroed, Overflux Orbs to powder, warps refilled, daily code usable). These are the only ones: `DateNow()` against a `player` field, plus `dayCheck`, read against the calendar by `dailyResetCheck`. A save is re-encoded with `encodeSave`, never `window.btoa`: GDS hooks it and would take that save for the current one.
- **A save exported by the game itself can be imported too** (a file that isn't a mod backup is read as one).
- **Refused while autosing is active**, export included: autosing turns three settings off for its run, so a file made then would hold them off.
- **CLEAR SETTINGS (Tools tab) goes through it** (`clearSettingsAndReload`): confirm, remove `hs-settings`, block writes, reload. The settings also live in memory and are written back whole at any setting change, so removing the key alone did nothing unless the player reloaded without touching anything.
- **Game preferences are a fourth part** (`GAME_PREF_KEYS`): what the game keeps in `localStorage` outside its save and reads at page load: `language`, `theme`, `statSymbols`, `synergism-tab-order`, `copyToClipboard`, `dismissedAnnouncements`. A missing key is a value too (default theme, export to a file; `copyToClipboard` is stored as an empty string), so an import removes the listed keys the file doesn't have. Only the listed keys are ever written from a file.
- Never in a backup: `firstPlayed` (also in the save) and `pendingTimeSkips` (bought time skips not applied yet, tied to the account).
- Test: `scripts/tests/test-backup-file.cjs` (the file filter, the import's writes and blocks, the rollback, the clock shift).
