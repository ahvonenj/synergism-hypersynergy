# Vanilla game behaviours to know (DOM, text, numbers)

The game's header has its own notes: `docs/features/header-*.md` (start with `header-modules.md`).

The game's DOM is not always an accurate picture of its state. Prefer the state itself (`HSGlobal.exposedPlayer`, GDS save data) or signals the game keeps up to date (such as toggle border colours) over displayed text.
- **Periodic display updates skip hidden tabs.** Every `visualUpdate*` function in `UpdateVisuals.ts` returns early unless its tab, and often its subtab, is active. Counters, levels and costs on a hidden tab are stale until it is opened.
- **Event-driven updates always run.** Code triggered by an action (a click handler, a toggle, a purchase, loading a loadout) writes to the DOM whatever tab is shown. For example, `setLastBlueberryLoadout()` updates the `activeBlueberryLoadout` class on all 16 loadout slots even when the Ambrosia tab is hidden, so a `MutationObserver` on them works.
- **Display updates pause while the offline popup is open** (`fastUpdates` skips `htmlInserts()` when `isOfflineDialogOpen()`). For example, the Misc stats, and so the stage patch, only render once the popup closes.
- **A language switch re-translates elements from their `i18n` attribute**, not from their state (`translateHTML()` in `i18n.ts`). Elements with a static `i18n` attribute (e.g. `#tesseractautobuytoggle`, `#tesseractautobuymode`) show the wrong text until redrawn. Other dynamic texts keep the old language until redrawn.
- **A reset sends the player to Buildings and forgets every subtab.** `singularity()` (`Reset.ts`) runs `resetAllSubTabs()`, `changeTab(Buildings)`, `changeSubTab(Buildings, page 0)`, and the save load that ends it (`reloadShit()`, `Synergism.ts`) runs them again: twice per singularity and per Exalt entry or exit (all synchronous), once for a save load or a page load. `resetAllSubTabs()` only clears the game's indexes: a hidden tab's subtab buttons keep their `active-subtab` class until that tab is opened again. Clicking a locked tab opens the next unlocked one, and clicking a locked subtab the next unlocked subtab, so check that a button is visible before clicking it. A patch must not skip `resetAllSubTabs()`: `switchSubTab` loops forever on a remembered subtab that is locked, with every later one.
- **`changeTab` blurs the focused element** (`Tabs.ts`), and the game's dialogs take the focus and answer the keyboard through a `keyup` listener on their popup (`UpdateHTML.ts`): code that changes tab while a dialog is shown must give it the focus back.
- **The offline popup shows at the end of the offline simulation**, not at its start, and not at all when `player.offlinetick` is 0 or the load is a reset (`importSynergism(…, true)`).
- **Every save load unmarks the ambrosia loadout** (`loadSynergy` calls `setLastBlueberryLoadout(0)`), singularities included.
- **The game's code numbers Exalts differently from the game screen** (`calculateExalt6*` is `limitedTime`, Exalt 7 on screen; `calculateExalt4*` is `noOcteracts`, Exalt 5), and its own texts disagree too. Name Exalts by the in-game order (`index.html`) or by name, never by a code number.
- **Text is translated.** Never compare game text against English. Use `HSUtils.getGameTranslation(key, vars?)` with the game's translation key, or a non-text signal.
- **Displayed numbers follow the browser locale, not the game language.** The game formats them with `new Intl.NumberFormat(undefined, …)` (`getFormatter` in `Synergism.ts`): `1,234.5` in English, `1 234,5` in French (narrow non-breaking spaces), `1.234,5` in German. Read them back with `HSNumberParser` (`hs-utils/hs-number-parser.ts`), never with `parseFloat` or a hand-written regex: it reads the separators, the digits and the exponent symbols from that same `Intl.NumberFormat(undefined)`. `parse(text)` returns the first number in the text (`NaN` if none), `parseAll(text)` all of them, `parseDecimal(text)` a break_infinity `Decimal` for values above 1.8e308. Limits: only for text formatted by Intl (a raw JS decimal like `1.5` is misread where `.` groups thousands; raw integers are fine); "first number" means the caller cuts the text when other digits can come before; the notations above e1,000,000 (`1.23e1.234M`, `E1.234e6`) give `NaN`.
- **Displayed numbers are cut, not exact.** `format()` (`Synergism.ts`) keeps 3 digits above 1e6 (above 1e12 when called with `long`) and truncates (`roundingMode: 'trunc'`): 2,048,000 and 2,049,999 both show `2.04e6`. A number read back from the DOM can be up to 1% too low, so never compare two of them to decide something (`HSHepteracts` did, to tell whether a quick expand expands; it now reads `exposedPlayer`, and only bookmarklet players still go through the meter's text).

## Breaks and errors that aren't the mod

- **A broken layout right after a game update can be the browser's cached CSS.** The game loads `Synergism.css` with no version or hash in its name, so the browser can keep the old CSS with the new `index.html`. Seen 2026-10-21: the update added a cleanse button (`#corruptionCleanseHeader`, a `.headerLoadoutSlot` with an img) whose `position: relative` lives only in the new CSS; with the old CSS, the slot-icon rule (`#mainHeader .headerLoadoutSlot > img`: absolute, inset 0, object-fit contain) drew `CorruptExit.png` over the whole window at every load. A hard reload (Ctrl+Shift+R) fixed it. When a layout break is reported right after a game update, check whether the new game source explains it with the new CSS (`local/game/`, `git log`), and ask for a hard reload before digging into the mod.
- **`TypeError: Cannot read properties of undefined (reading 'replace')` in the game bundle, twice per page load when logged out.** The game's `eventHotkeys` (`Hotkeys.ts`) runs `event.code.replace(/^(Digit|Numpad)/, …)` on every `keydown` reaching `document`, and a keydown without `code` throws. The mod and both loaders never send a keydown. Likely cause (accepted, not proven): logged out, the page holds the game's sign-in form (`#email-si`, `#password-si`), and the browser's autofill fills it with fake keydowns released at the first interaction after the page load (a tab click, or a console command, which Chrome counts as a user gesture). Check after the fact with `[...document.querySelectorAll('input:autofill')].map(e => e.id)`; a listener pasted in the console is too late (the paste is itself the first interaction). Harmless and vanilla.
- **Repeated `WebSocket connection to 'wss://synergism.cc/consumables/connect' failed` lines are expected when logged out** (the game's own socket).
- **`Uncaught ZodError` on every save and export, with path `seed`: an RNG seed overtook the clock.** The save schema wants each `player.seed` below `Date.now() + 1000` (`PlayerSchema.ts`), and each draw adds 1 to a seed that began as a timestamp in ms (`RNG.ts`; a singularity puts them back at the page load's time). So over 1000 draws per second on average, saves fail; one Ambrosia bar fill is one draw (reported by a player in Exalt 10, whose Ambrosia seed had reached the clock). Reproduced with the mod off, by pushing the seed past the clock. The patcher's save seed cap saves a copy with the seeds capped at the clock (`report.saveSeedCap`); remove it once the game drops that upper bound.
- **A throw in one of the game's `setInterval` callbacks ends that interval until the page reloads.** `worker-timers` reschedules an interval only after its callback returned (`Timers.ts` uses it in a browser). So one failed autosave stops the autosave for the session, with nothing shown; manual saves and exports still write.
